# Настройка приложения «Закупки Китай»

Инструкция для человека, который никогда не работал с Google Cloud. Нужно один раз пройти шаги 1–9, дальше приложение работает само. На всё уходит около 30–40 минут.

**Что получится:** приложение по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`, вход своим Google-аккаунтом, данные в вашей Google-таблице, курсы ВТБ подгружаются каждый день.

**Зачем всё это нужно.** У приложения нет своего сервера: оно работает в браузере и ходит в вашу Google-таблицу напрямую. Чтобы Google это разрешил, приложению нужен «пропуск» — идентификаторы из вашего собственного проекта Google Cloud. Проект бесплатный, платёжную карту привязывать не нужно (используемые API бесплатны).

Что вы получите в итоге и куда это вписывается:

| Что | Откуда берётся | Куда вписывается |
|---|---|---|
| `VITE_GOOGLE_CLIENT_ID` — идентификатор клиента OAuth | шаг 5 | переменная репозитория GitHub |
| `VITE_GOOGLE_API_KEY` — ключ API | шаг 6 | переменная репозитория GitHub |
| `VITE_GOOGLE_APP_ID` — номер проекта | шаг 7 | переменная репозитория GitHub |

Это публичные идентификаторы: они защищены не секретностью, а ограничением по адресу сайта (шаги 5 и 6). Пароли и секретные ключи не нужны.

> Названия пунктов в Google Cloud даны по-русски и в скобках по-английски: интерфейс зависит от языка вашего аккаунта, а Google иногда переименовывает разделы. Если пункта нет — ищите по английскому названию или через строку поиска вверху консоли.

## 0. Что понадобится

- Google-аккаунт (обычный `@gmail.com` подходит).
- Аккаунт на [github.com](https://github.com) и репозиторий с этим кодом. Репозиторий должен быть **публичным** (GitHub Pages на бесплатном тарифе работает только с публичными). Коммерческие данные в репозиторий не кладутся — они только в вашей Google-таблице.
- Название репозитория не должно быть вида `<логин>.github.io`: приложение рассчитано на адрес с именем репозитория в конце.

## 1. Создайте проект Google Cloud

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/) и войдите нужным аккаунтом. Если Google просит принять условия — примите.
2. Вверху слева нажмите на название текущего проекта (рядом с логотипом Google Cloud) и в открывшемся окне — **«Создать проект» (New project)**.
3. Название: например, `zakupki-china`. Организацию (Organization) и расположение (Location) оставьте как есть. Нажмите **«Создать» (Create)**.
4. Дождитесь уведомления о создании и убедитесь, что вверху выбран именно этот проект.

## 2. Включите четыре API

Откройте **☰ → «API и сервисы» → «Библиотека» (APIs & Services → Library)**. Для каждого из четырёх API найдите его через поиск, откройте карточку и нажмите **«Включить» (Enable)**:

1. **Google Sheets API** — чтение и запись таблицы.
2. **Google Drive API** — создание таблицы и доступ к выбранному файлу.
3. **Google Picker API** — окно «Выбрать существующую таблицу».
4. **Apps Script API** — установка скрипта курсов в таблицу.

Быстрые ссылки (откройте и нажмите «Включить», убедившись, что выбран ваш проект):
[Sheets](https://console.cloud.google.com/apis/library/sheets.googleapis.com) ·
[Drive](https://console.cloud.google.com/apis/library/drive.googleapis.com) ·
[Picker](https://console.cloud.google.com/apis/library/picker.googleapis.com) ·
[Apps Script](https://console.cloud.google.com/apis/library/script.googleapis.com).

## 3. Настройте экран согласия OAuth (режим тестирования)

Это окно, которое вы увидите при входе в приложение: «Приложение запрашивает доступ…». Для личного приложения его не нужно отправлять на проверку Google — достаточно оставить в режиме тестирования.

Откройте **☰ → «API и сервисы» → «Экран согласия OAuth» (APIs & Services → OAuth consent screen)**. В новом интерфейсе этот раздел называется **«Google Auth Platform»**, и в нём есть вкладки «Брендинг», «Аудитория», «Доступ к данным», «Клиенты». Если видите кнопку **«Начать» (Get started)** — нажмите её и пройдите мастер:

1. **Информация о приложении (App information).** Название — `Закупки Китай`. Адрес поддержки (User support email) — ваша почта.
2. **Аудитория (Audience).** Выберите тип пользователей **«Внешний» (External)**. «Внутренний» доступен только корпоративным аккаунтам Google Workspace.
3. **Контактные данные (Contact information).** Ваша почта.
4. Примите политику и нажмите **«Создать» (Create)**.

Затем:

5. Откройте **«Аудитория» (Audience)**. Статус публикации должен быть **«Тестирование» (Testing)** — не переводите его в «В production».
6. В блоке **«Тестовые пользователи» (Test users)** нажмите **«Добавить пользователей» (Add users)** и впишите почту каждого человека, который будет входить в приложение — **включая вашу собственную**. Сохраните. Войти смогут только эти аккаунты.
7. Откройте **«Доступ к данным» (Data access)** → **«Добавить или удалить области» (Add or remove scopes)** и добавьте четыре области (если их нет в списке — вставьте адреса в поле «Добавить области вручную»):
   - `https://www.googleapis.com/auth/drive.file`
   - `https://www.googleapis.com/auth/script.projects`
   - `openid`
   - `email`

   Нажмите «Обновить» (Update) и «Сохранить» (Save).

### Что важно знать про режим тестирования

- **Предупреждение «Google не проверила это приложение».** При первом входе Google покажет страницу с таким текстом. Это нормально: приложение — ваше собственное, и проверку Google проходят только публичные сервисы. Ничего не сломалось. Как пройти: нажмите **«Дополнительные настройки» (Advanced)** → **«Перейти на страницу … (небезопасно)» (Go to … (unsafe))**, затем отметьте галочки доступа и нажмите «Продолжить».
- **Лимит 100 тестовых пользователей.** В режиме тестирования войти могут не более 100 аккаунтов из списка. Для одного человека или небольшой команды этого с запасом. Если понадобится больше — это уже публичное приложение с проверкой Google, в рамках этой инструкции не рассматривается.
- **Только перечисленные аккаунты.** Если войти пытается кто-то, кого нет в списке тестовых пользователей, Google ответит «Доступ заблокирован». Добавьте его почту в шаге 6.
- **Повторный вход.** В режиме тестирования Google может чаще просить войти заново (например, раз в неделю). Просто нажмите «Войти через Google» ещё раз — данные в таблице не теряются.

## 4. Опубликуйте код на GitHub и включите Pages

Адрес сайта нужен для следующих шагов, поэтому сначала включим Pages.

1. На странице вашего репозитория откройте **Settings → Pages**.
2. В блоке **Build and deployment → Source** выберите **GitHub Actions**.
3. Адрес сайта будет таким: `https://<ваш-логин>.github.io/<имя-репозитория>/`. Запомните его: в шагах 5 и 6 понадобится часть до имени репозитория — `https://<ваш-логин>.github.io` (без слэша в конце и без имени репозитория).

Саму публикацию мы запустим в шаге 8, когда будут готовы идентификаторы.

## 5. Создайте OAuth Client ID

1. **☰ → «API и сервисы» → «Учётные данные» (APIs & Services → Credentials)** — либо в новом интерфейсе **Google Auth Platform → «Клиенты» (Clients)**.
2. **«Создать учётные данные» → «Идентификатор клиента OAuth» (Create credentials → OAuth client ID)**, либо в новом интерфейсе **«Создать клиента» (Create client)**.
3. **Тип приложения (Application type): «Веб-приложение» (Web application).** Название — `Закупки Китай (веб)`.
4. В блоке **«Разрешённые источники JavaScript» (Authorized JavaScript origins)** нажмите **«Добавить URI» (Add URI)** и впишите:
   - `https://<ваш-логин>.github.io` — только это, без пути, без `/<имя-репозитория>/` и без слэша в конце;
   - если собираетесь запускать приложение у себя на компьютере (`npm run dev`) — ещё `http://localhost:5173`.
5. Блок **«Разрешённые URI перенаправления» (Authorized redirect URIs)** оставьте пустым — приложению он не нужен.
6. Нажмите **«Создать» (Create)**. Появится окно с **идентификатором клиента** — строка вида `1234567890-abcdef.apps.googleusercontent.com`. Скопируйте её: это значение `VITE_GOOGLE_CLIENT_ID`.

   «Секрет клиента» (Client secret), если Google его показывает, приложению не нужен — нигде не вписывайте.

> Изменения в источниках JavaScript могут применяться до нескольких минут, иногда дольше.

## 6. Создайте API key (ключ API) с ограничением по домену

Ключ нужен только для окна выбора таблицы (Picker). Ограничение по домену не даёт другим сайтам им пользоваться.

1. **«API и сервисы» → «Учётные данные» → «Создать учётные данные» → «Ключ API» (Create credentials → API key)**.
2. Откроется окно с ключом. Скопируйте его — это `VITE_GOOGLE_API_KEY` — и нажмите **«Изменить ключ API» (Edit API key)** (либо позже: «Учётные данные» → имя ключа).
3. Название — `Закупки Китай (Picker)`.
4. **«Ограничения для приложений» (Application restrictions)** → **«Сайты» (Websites / HTTP referrers)** → **«Добавить» (Add)**:
   - `https://<ваш-логин>.github.io/*`
   - для локального запуска ещё `http://localhost:5173/*`

   Указывайте именно так — с `/*` после домена и **без** имени репозитория: браузер передаёт Google только домен, и адрес с путём ключ отклонит.
5. **«Ограничения API» (API restrictions)** → **«Ограничить ключ» (Restrict key)** → отметьте **Google Picker API** → «ОК».
6. **«Сохранить» (Save)**.

## 7. Узнайте App ID (номер проекта)

App ID — это **номер проекта** Google Cloud (только цифры, обычно 12 знаков), он нужен окну выбора таблицы.

1. Откройте [console.cloud.google.com/home/dashboard](https://console.cloud.google.com/home/dashboard) и в блоке **«Информация о проекте» (Project info)** найдите **«Номер проекта» (Project number)**. Либо **☰ → «IAM и администрирование» → «Настройки» (IAM & Admin → Settings)**.
2. Скопируйте число — это `VITE_GOOGLE_APP_ID`.

Не путайте с «Идентификатором проекта» (Project ID, например `zakupki-china-123456`) — нужен именно **номер**.

## 8. Впишите переменные в GitHub и опубликуйте

1. В репозитории откройте **Settings → Secrets and variables → Actions** и вкладку **Variables** (не «Secrets»).
2. Нажмите **New repository variable** и создайте три переменные — имя строго как написано, значение — то, что вы скопировали:

   | Имя | Значение |
   |---|---|
   | `VITE_GOOGLE_CLIENT_ID` | идентификатор клиента из шага 5 |
   | `VITE_GOOGLE_API_KEY` | ключ API из шага 6 |
   | `VITE_GOOGLE_APP_ID` | номер проекта из шага 7 |

3. Запустите публикацию: либо сделайте push в ветку `main`, либо откройте вкладку **Actions → Deploy to GitHub Pages → Run workflow**.
4. Дождитесь зелёной галочки (1–3 минуты). Workflow сам запускает проверку (`npm run check`), собирает приложение и публикует его. Адрес сайта показывается в конце задачи `deploy` и в **Settings → Pages**.
5. Если задача красная — откройте её в Actions и посмотрите, на каком шаге ошибка. Если не сработал шаг проверки, публикации не будет, и это правильно.

Переменные подставляются **при сборке**: если вы поменяли значение переменной, запустите workflow заново (Run workflow).

## 9. Включите Apps Script API в своём аккаунте

Это отдельная галочка именно в вашем аккаунте Google — не в Cloud-проекте. Без неё приложение не сможет поставить в таблицу скрипт ежедневных курсов (всё остальное работает).

1. Откройте [script.google.com/home/usersettings](https://script.google.com/home/usersettings) тем же аккаунтом, которым будете входить в приложение.
2. Включите переключатель **«Google Apps Script API» (Google Apps Script API)** в положение «Вкл».
3. Подождите минуту-две, пока настройка применится.

Если вы пропустили этот шаг, приложение само покажет подсказку со ссылкой и кнопкой «Повторить».

## Первая привязка таблицы

1. Откройте адрес сайта из шага 8. На экране входа нажмите **«Войти через Google»**.
2. Выберите аккаунт (он должен быть в списке тестовых пользователей, шаг 3). Пройдите предупреждение «Google не проверила это приложение» (описано в шаге 3) и **оставьте включёнными все галочки доступа** — иначе приложение не сможет создать таблицу и скрипт.
3. Выберите, что делать с таблицей:
   - **«Создать новую таблицу»** — приложение создаст таблицу у вас на Google Диске и само заведёт в ней листы и колонки;
   - **«Выбрать существующую»** — откроется окно Google; выберите таблицу. Приложение добавит недостающие листы и колонки и **не удалит и не сдвинет ваши данные**. Старую таблицу «Закупки Китай AREC» таким способом подключать не нужно — её данные переносит отдельный экран «Импорт» в самом приложении.
4. Приложение настроит листы и установит в таблицу скрипт. Появится **«Таблица подключена»**. Если скрипт не установился, прочитайте подсказку на экране (чаще всего — не выполнен шаг 9) и нажмите «Повторить».
5. Нажмите **«Начать работу»**. Запоминается привязка в этом браузере: в следующий раз приложение откроет ту же таблицу сразу после входа.

## Ежедневные курсы ВТБ

Скрипт в таблице умеет загружать курсы продажи USD, EUR и CNY (юань) в лист «Курсы». Google не позволяет включить ежедневный запуск без вашего разрешения внутри самой таблицы, поэтому один раз:

1. Откройте таблицу (ссылка есть в приложении на экране подключения; также она лежит в вашем Google Диске).
2. Если меню **«Закупки»** не видно — обновите страницу таблицы (F5). Меню появляется рядом с «Справка».
3. Выберите **«Закупки» → «Включить ежедневные курсы»**.
4. Google попросит разрешение для скрипта (окно «Требуется авторизация»). Нажмите «Просмотреть разрешения», выберите аккаунт; на странице «Google не проверила это приложение» — **«Дополнительные настройки» → «Перейти на страницу … (небезопасно)»** → **«Разрешить»**. Разрешение запрашивается только для этой таблицы.
5. Запустите пункт меню ещё раз, если после разрешения ничего не произошло. Скрипт создаст ежедневный запуск (около 10:00 по Москве) и сразу загрузит сегодняшние курсы. Повторное нажатие безопасно: лишних запусков не появится.

Другие пункты меню:

- **«Закупки» → «Обновить курсы сейчас»** — загрузить сегодняшние курсы немедленно.
- **«Закупки» → «Проверить источник курсов»** — диагностика (см. ниже).

### Если курсы не загружаются

Официального API у ВТБ нет, поэтому скрипт читает страницу сайта, и формат этой страницы мог измениться или оказаться недоступным для серверов Google. Что делать:

1. В таблице выберите **«Закупки» → «Проверить источник курсов»**.
2. Откройте лист **«Лог»** и **пришлите разработчику его содержимое целиком** (скопируйте все строки или сделайте снимок экрана). В нём записаны адрес источника, код ответа сайта, начало ответа и результат разбора — по этому можно починить разбор.
3. Пока это не починено, курсы можно вносить вручную на экране «Курсы» в приложении: ручной курс на дату имеет приоритет над автоматическим, и расчёты продолжают работать.
4. Адрес страницы-источника лежит в листе **«Настройки»**, ключ `ratesSourceUrl`. Если у ВТБ изменился адрес — поменяйте значение там.

## Установка приложения как иконки (PWA)

Приложение можно открывать просто в браузере, а можно поставить как обычную программу: отдельное окно или иконка на домашнем экране. Ставится оно из браузера, никаких магазинов приложений не нужно. Сначала откройте адрес сайта из шага 8.

### Windows

- **Chrome или Edge:** в правой части адресной строки появится значок установки (экран со стрелкой) — нажмите **«Установить»**. Если значка нет: меню **⋮ → «Приложения» → «Установить этот сайт как приложение»** (Edge: **… → «Приложения» → «Установить этот сайт как приложение»**; Chrome: **⋮ → «Трансляция, сохранение и общий доступ» → «Установить страницу как приложение»**).
- Иконка появится в меню «Пуск» и, если разрешите, на рабочем столе.

### Linux

- **Chrome, Chromium, Edge, Brave:** так же, как на Windows — значок установки в адресной строке или меню **⋮ → «Установить Закупки…»**. Иконка появится в меню приложений.
- **Firefox на компьютере** установку приложений не поддерживает — используйте один из браузеров выше или откройте сайт обычной вкладкой.

### Android

1. Откройте адрес сайта в **Chrome**.
2. Меню **⋮ → «Установить приложение»** (на некоторых версиях — «Добавить на главный экран»). Подтвердите.
3. Иконка «Закупки» появится на домашнем экране и в списке приложений.

### iPhone и iPad (iOS)

1. Откройте адрес сайта в **Safari** (на iOS установка выполняется из Safari).
2. Нажмите кнопку **«Поделиться»** (квадрат со стрелкой вверх) внизу экрана.
3. Прокрутите список и выберите **«На экран "Домой"» (Add to Home Screen)**, затем **«Добавить»**.
4. Иконка появится на домашнем экране. Запускайте приложение с неё.

Если вход через Google из иконки на домашнем экране не открывается или зацикливается, один раз войдите через обычную вкладку Safari, а затем возвращайтесь к иконке.

### Обновления

Приложение обновляется автоматически: после новой публикации оно подтянет свежую версию при следующем запуске (иногда со второго раза). Данные от этого не зависят — они в вашей таблице.

## Частые проблемы

| Что видите | Что делать |
|---|---|
| Нет кнопки «Войти через Google», только «Попробовать без Google» | При сборке не заданы переменные (шаг 8) или заданы неверно. Проверьте имена, затем запустите workflow заново. |
