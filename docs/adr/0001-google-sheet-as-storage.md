## Контекст

Все данные уже живут в большой Google-таблице; пользователь один на таблицу, каждый подключает свою («мне нравится вариант с гугл таблицами»). Приложение размещается на GitHub Pages — это только статические файлы.

## Решение

Данные хранятся в Google-таблице пользователя, своего сервера нет. Приложение — клиент в браузере: при открытии читает все листы в память, дальше записывает изменения по одной записи. Доступ к данным спрятан за интерфейсом хранилища; вторая его реализация держит данные в браузере и служит демо-режимом и основой тестов без Google.

## Почему

- **Свой сервер с базой данных** отвергнут: нужны хостинг, учётные записи и забота о чужих коммерческих данных, а приложение рассчитано на одного человека на таблицу и живёт на статическом хостинге. Таблица уже есть, её привычно открывать и править глазами.
- **Хранить всё только в браузере** отвергнуто как основной режим: приложение ставится на четыре платформы, а данные одного пользователя должны быть общими между устройствами. В таком виде оставлен лишь демо-режим.
- **Кэш данных для работы без сети** отвергнут требованием: работа без интернета не нужна, кэшируется только оболочка.

## Последствия

- Без сети приложение бесполезно: показывает баннер «Нет связи с таблицей — повторить», введённое в форме не теряется.
- Загрузка идёт целиком; на сильно выросшей таблице она замедлится. Порог не измеряли.
- Правки, сделанные в таблице руками, приложение увидит только после повторной загрузки; защиты от ручной порчи структуры, кроме проверок при привязке (0002), нет.
- Лимиты Sheets API становятся нашими лимитами; своего слоя кэша и очередей нет.
- Перейти на другое хранилище можно, написав новую реализацию интерфейса хранилища, но формат листов (0004) придётся переносить.
