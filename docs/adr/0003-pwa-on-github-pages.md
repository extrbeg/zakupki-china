## Контекст

Нужно приложение на Windows, Linux, Android и iPhone; в брифе «PWA ок». Публикация — на GitHub Pages, репозиторий публичный, вход — в Google-аккаунт пользователя.

## Решение

Приложение — PWA, размещённое на GitHub Pages. Маршруты строятся на хэше адреса. Вход идёт через OAuth-клиент из Google Cloud самого пользователя; идентификаторы клиента не вшиты в репозиторий, а берутся из локального файла окружения и переменных репозитория. Без них вход Google скрыт, доступен только демо-режим. Сервис-воркер кэширует только оболочку. Коммерческие данные в git не попадают: выгрузка реальной таблицы лежит вне репозитория, в git — синтетическая фикстура. Публикация — только с подтверждения пользователя.

## Почему

- **Нативные сборки для магазинов приложений** отвергнуты: четыре платформы, один пользователь, он согласился на установку иконкой.
- **Обычная адресация страниц без хэша** отвергнута: GitHub Pages не умеет отдавать одностраничному приложению глубокие ссылки, прямой переход на внутренний адрес дал бы 404.
- **Кэш данных в сервис-воркере** отвергнут требованием работы без интернета: оболочка кэшируется, данные нет.
- **Вшить идентификаторы клиента в сборку в репозитории** отвергнуто: даже ограниченные доменом, они не должны жить в публичном репозитории.

## Последствия

- Адреса вида `#/orders/…`; ссылки некрасивы, но работают.
- На iPhone установка только вручную через Safari («На экран Домой»), без предложения установить.
- Чтобы приложение заработало с Google, пользователь один раз проходит `docs/setup.md`: проект Google Cloud, экран согласия, тестовые пользователи, Client ID, ключ для окна выбора файла, переменные репозитория. До этого — демо.
- Проверка, что реальные данные не утекли в публичный репозиторий, держится на `.gitignore`; референсный тест на реальных данных пропускается у всех, у кого нет приватной выгрузки.
